Section 01
What needs to be installed
One-time setup per machine. Anyone who edits and pushes needs all three.
1
Python 3
Check if already installed:
python3 --version
If not installed, download from python.org.
2
openpyxl
pip install openpyxl
3
Git
Check if already installed:
git --version
If not, download from git-scm.com. Also make sure the machine is signed into GitHub.
Section 02
One-time repo setup
Done once by Pragati (or whoever handles initial setup). Requires write access to the org.

The repo contains four files, all in the same folder:
dspg-2026-curriculum-/ ├── curriculum-2026.xlsx ← edit this to update the curriculum ├── generate_curriculum.py ← run this after every Excel change ├── dspg_curriculum_2026.html ← auto-generated, never edit manually └── README.md ← shown on the GitHub repo page
1
Create the repo on GitHub
Go to the org → New repository → name it dspg-2026-curriculum- → set to Public → click Create repository.
⚠️
Do not check "Add a README file." Initializing with a README causes a conflict on the first push.
2
Push the files to GitHub
From inside the folder:
cd dspg-2026-curriculum-
git init
git add .
git commit -m "initial curriculum upload"
git branch -M main
git remote add origin https://github.com/VT-Data-Science-For-The-Public-Good/dspg-2026-curriculum.git
git push -u origin main
3
Turn on GitHub Pages
Repo → Settings → Pages → Source: Deploy from a branch → branch: main, folder: / (root) → Save.
Wait about a minute, then refresh the page. The live URL will appear:
https://vt-data-science-for-the-public-good.github.io/dspg-2026-curriculum/dspg_curriculum_2026.html
✅
This is the only link anyone needs. Bookmark it — it always shows the latest version.
4
Add collaborators
Repo → Settings → Collaborators and teams → add grad fellows and faculty by GitHub username.
opt
Add a .gitignore for Excel temp files
When Excel is open it sometimes creates a temp file starting with ~$. If that file shows up in commits, run this once:
echo "~\$*.xlsx" >> .gitignore
git add .
git commit -m "ignore Excel temp files"
git push
Section 03
First-time setup for new team members
Anyone who wants to edit and push needs to do this once. Anyone who only views the curriculum just needs the URL — skip this entirely.
1
Install Python, openpyxl, and Git
Follow Section 01.
2
Clone the repo
Downloads all files to the local machine. Only needed once.
git clone https://github.com/VT-Data-Science-For-The-Public-Good/dspg-2026-curriculum.git
cd dspg-2026-curriculum-
3
From now on — follow the update workflow
After cloning, never clone again. Every update starts with git pull and ends with git push. See Section 04.
Section 04
Update workflow
Every time the schedule changes. Takes about 2 minutes.
1
Always pull first
Skipping this causes push conflicts if someone else has pushed since the last pull.
cd dspg-2026-curriculum-
git pull
2
Edit the Excel, save, and close it
Open curriculum-2026.xlsx from inside the repo folder. Make changes, save, and close before running the script.
Always edit the Excel from inside the repo folder. Editing a copy elsewhere (Downloads, Desktop) and then pushing will read the wrong file.
3
Regenerate the HTML
Run with your name so it shows in the footer who last updated it:
python generate_curriculum.py --by "Your Name"
For example: python generate_curriculum.py --by "Pragati" or --by "Jesse". The footer will show: Generated April 10, 2026, 12:46 PM · Pragati
Running without --by also works — no name will appear in the footer.
4
Commit and push
git add .
git commit -m "describe what changed"
git push
Live site updates within about a minute.
Section 05
How to edit the Excel correctly
The script reads specific columns in a specific order. Do not rename columns, reorder them, or change the row format — even small changes will break the output.
A
Master sheet — one row per week
Col A Col B Col C Col D
Week number
e.g. Week 1		 Week title
shown on TOC card		 Milestone
blue badge on week page		 Deliverable
green badge on week page
B
Week sheets — day rows
Each week sheet starts with a title row, then a header row, then the daily schedule. The script reads by column position.
Col A Col B Col C Col E
Date
e.g. Tue, May 26		 Day title
e.g. Onboarding and Introduction		 leave empty leave empty
empty Activity name
e.g. Workshop - Introduction to Research		 Time
e.g. 9:00 AM - 10:20 AM		 Who
e.g. Dr. Le Wang
• Col A has a date → new day card. Col A is empty → sub-event under that day.
• Section labels like Morning: or Afternoon: in col B are ignored automatically.
• Col D (Location) is stored but not displayed in the curriculum.
C
Week sheets — deliverables
Add deliverables at the bottom of each week sheet. The label in col A must contain the word Deliverables.
Col A Col B
Week 1 Deliverables: Start a draft of literature review
empty A more refined research question based on literature review
⚠️
Col A must contain the word Deliverables — e.g. Week 1 Deliverables: or Week 4 Deliverables:. The deliverable text must be in col B, not col C or col D. Additional deliverables go in rows below with col A empty and text in col B.
D
Card colors — automatic
Assigned based on keywords in the activity name. No extra column needed.
Keyword in activity name Color
Workshop / Training / Lecture / Seminar Purple
Deliverable / Deadline / Submit / Deploy Green
Everything else Blue
E
Holidays
A day is auto-marked as a holiday if the day title (col B) contains any of these words:
holiday no activities memorial day independence day labor day thanksgiving
Example: Memorial day - no activities → auto-marked as holiday. Holiday days are still clickable but show a banner instead of events.

Section 07
Questions to discuss
Before going live
Q1
Public vs. private repo
The current plan is a public repo. If a private repo is preferred, VT may have GitHub Education access that enables private Pages for free — worth checking with IT before setup.
Q2
Same org or separate?
The DSPG team already uses VT-Data-Science-For-The-Public-Good for final project deliverables. Should the curriculum repo live under the same org, or separately?
Q3
Who has write access
Confirm the list of GitHub usernames to add as collaborators before setup.
Q4
Update frequency
How often should the HTML be regenerated and pushed: after every edit, on a fixed schedule, or only before key meetings? Should we put someone responsible for keeping the live link current?
Q5
URL shortening
The GitHub Pages URL is long. Consider a short redirect (e.g. via bit.ly) before sharing with interns and stakeholders.
💡
Weeks 4–7 are incomplete
Currently only topic-level rows. Once the detailed schedule is ready, add rows using the same format as Weeks 1–3 and run the script — they will update automatically.
💡
Weeks 8–10 are empty
No content yet. Add rows using the day-by-day format when ready and run the script.
